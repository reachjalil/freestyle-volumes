# v0.1.0 verification — 2026-09-17

Everything below was run on a macOS host with Docker Desktop 27.3.1 (Linux 6.8.0-47-generic aarch64 VM). Each tier is listed with exactly what it proves. Nothing here was run on Freestyle.

## Unit tests (mocked sandbox, in-memory object store)

`pnpm test`: 33 tests, 33 pass. Covers input validation (names, mount paths, subpaths, prefixes, buckets, shell quoting, protected roots), storage config resolution and rclone environment generation, storage error classification, the registry (create/get/list/delete, namespaces, attachment gating, corrupt records), generated guest scripts (parsed with `sh -n`, no credential strings, pinned rclone version and checksums), guest output parsing, and error mapping for every bootstrap, mount and detach failure code. `pnpm check:types` compiles the real `freestyle@0.2.13` client and `Vm` against the adapter's structural types. `pnpm check:examples` type-checks both examples.

## Linux integration tests (Docker + MinIO, real rclone FUSE mounts)

`pnpm test:integration`: 10 tests, 10 pass, 26 s. Sandboxes are `rclone/rclone:latest` (Alpine, rclone 1.75.1) containers with `--device /dev/fuse --cap-add SYS_ADMIN`; storage is `quay.io/minio/minio:latest`. The library's `dockerSandboxes()` adapter runs the same guest scripts the Freestyle adapter would.

| Test | Result |
| :--- | :--- |
| create, attach, write, flush, detach, reattach in a fresh container, replacement seen by the first container, idempotent attach/detach | pass; objects verified in the bucket (`hello.txt`, `dir/nested.txt`, `emptydir/` marker); credentials absent from every `/proc/*/cmdline` |
| read-only attach | pass; write fails with "Read-only file system", mismatched read-only re-attach at the same path refused |
| namespace and subpath isolation | pass; two prefixes with same-named volumes stay separate; a `users/alice` subpath mount cannot reach `users/bob`; deleting one tenant's volume leaves the other's data |
| invalid credentials and unavailable storage | pass; `STORAGE_AUTH` and `STORAGE_UNREACHABLE` raised on the host before any sandbox exec, no mount state created |
| mount failure and timeout inside the sandbox | pass; unresolvable endpoint → `MOUNT_FAILED` with log tail; blackhole endpoint → `MOUNT_TIMEOUT` within the bound, process killed, mount point cleaned, inspect reports `absent` |
| sandbox without /dev/fuse | pass; `FUSE_UNAVAILABLE` before any install |
| interrupted writes | pass; write buffered (`uploads.queued = 1`), rclone killed with SIGKILL, inspect → `stale`, object absent from the bucket, plain detach refused with `MOUNT_STALE`, re-attach resumes the cached upload, detach → `flushed: true`, object content verified |
| busy mount | pass; open file handle → `MOUNT_BUSY`, mount stays; `force` detaches with `flushed: false` |
| flush failure | pass; MinIO paused → `FLUSH_FAILED`, mount still attached; MinIO resumed → detach flushes, object present |
| delete | pass; refused with `VOLUME_IN_USE` while attached, then removes only that volume's prefix |

`VOLUMES_TEST_BOOTSTRAP=1`: the bare `ubuntu:24.04` bootstrap test passes in 17 s: apt installs `fuse3` and `curl`, rclone 1.75.1 is downloaded from downloads.rclone.org and its SHA-256 verified, the mount comes up, a write is flushed to the bucket on detach.

## Manual probes that shaped the design (not part of the suite)

Before writing the library, four shell probes ran the raw mechanics in the same Docker setup and established: rclone's `--daemon` mode cannot host the rc socket (bind conflict), so rclone is backgrounded with `setsid` and a pid file; a killed rclone leaves a stale FUSE entry that fools `/proc/mounts`-only readiness checks and a stale socket file that blocks restarts; `vfs/queue-set-expiry` with `expiry=0` uploads immediately; a clean `fusermount3 -u` makes rclone exit and remove its socket; `--allow-other` lets non-root users write, `--uid/--gid` change the reported owner; bad credentials and unreachable endpoints fail at rclone startup; on restart with the same cache directory rclone re-queues dirty files.
