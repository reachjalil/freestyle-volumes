# v0.2.0 verification

## Pre-release run — 2026-09-25

Run on the release branch before publishing, on macOS (Darwin 25.5.0) with Node v26.4.0 and Docker 27.3.1 (Docker Desktop, linux/arm64 guests). CI repeats the unit, type, package and integration tiers on linux/amd64 with Node 22, 24 and 26 once the branch is pushed.

- **Unit:** `pnpm test`: 146 passed, 0 skipped. That is the 112 tests of the final 0.1.x main run plus 34 new ones covering the CLI (argument parsing, configuration, exit codes, secret redaction and every command against an in-memory store and scripted VMs), `FreestyleSandbox` (user, the 300 s exec cap, env forwarding, result mapping), `createVolumeReadySnapshot` (builder VM options, bootstrap failures, cleanup, validation), `storageConfigFromEnv`, `listMounts`/`detachAll`, and the preflight checks. The new listing and check scripts run for real in a local shell with only Linux probes faked (`test/helpers/local-sandbox.mjs`), across prepared, fresh, denied and bare-image scenarios; `checkStorage` runs against stores that enforce, ignore or reject conditional creates and that cannot list or delete.
- **Type checks:** `pnpm check:types` passed against `freestyle@0.2.14`, now also assigning the real SDK client to `FreestyleSnapshotClientLike` and SDK firewall specs to `FreestyleFirewallSpec` in both directions. `pnpm check:examples` passed, including the new `examples/prepare-snapshot.ts`.
- **Package:** `pnpm test:package` passed. It packs the tarball, installs it into a fresh project with `freestyle@0.2.14`, imports every entry point (and `require()` of the root, since the runtime supports `require(esm)`), runs the installed `freestyle-volumes` bin, and type-checks a consumer under `nodenext` (with library checks), `bundler` and `node10`. `npm publish --dry-run` ran the same checks through `prepublishOnly` and listed 69 files (151.3 kB packed, 622.7 kB unpacked). `publint`: all good. `@arethetypeswrong/cli`: every entry point resolves under node10, node16 ESM and bundler; node16 CommonJS gets the expected ESM-only warning.
- **Integration:** `VOLUMES_TEST_BOOTSTRAP=1 pnpm test:integration`: 33 passed, 0 failed, 0 skipped. That is the 26 tests of the final 0.1.x main run plus 7 new ones. The CLI tests drive the real bin through create, attach, write, inspect, detach, read-back and delete, then `doctor --vm`, `mounts` and `detach-all`, and check that failures exit 1. The others prove against MinIO that conditional creates are enforced and the probe is removed; that wrong credentials fail both on the host and from inside a container; that a container without FUSE fails the right check; that `listMounts` and `detachAll` drain two managed mounts while leaving an unmanaged `rclone mount` alone; and that a crashed mount is listed as `stale`, keeps `detachAll` from reporting `flushed`, and recovers through reattach. The suite still includes the bare `ubuntu:24.04` bootstrap, rclone 1.68.0 and 1.75.1, the small real multipart fixture and Git on real FUSE.
- **Workflows:** `actionlint` 1.7.12 reported nothing for `ci.yml`, `release.yml` and `freestyle-live.yml`. The release and live workflows have not run: they need a push, npm access and Freestyle secrets.
- **Freestyle live:** `pnpm test:freestyle`: 2 skipped. The round-trip test needs `FREESTYLE_API_KEY`, `VOLUMES_S3_BUCKET`, `VOLUMES_S3_ACCESS_KEY_ID` and `VOLUMES_S3_SECRET_ACCESS_KEY`; the snapshot test additionally needs `VOLUMES_TEST_PREPARE_SNAPSHOT=1`. **No live Freestyle round trip, snapshot build or pause/resume has been validated.** The manual Freestyle live test workflow runs both tests once the repository has the secrets.

## Live Freestyle run — 2026-09-25

A dedicated Freestyle team and API key; VMs from `freestyle/ubuntu-sm` (Ubuntu 24.04.5 LTS, x86_64, 16 GB disk). Storage: a dedicated Cloudflare R2 test bucket (location WNAM) with an account API token limited to Object Read & Write on that bucket; each run used its own prefix. Afterwards no test VM or snapshot remained on the team and the bucket held 0 objects.

- **R2 from the host:** `freestyle-volumes doctor`: all 5 storage checks passed, including `conditional-create` (R2 rejected the second `If-None-Match: *` write) and `bucket` (`HeadBucket` works with the bucket-scoped token).
- **Suite:** `node --env-file=.env.freestyle --env-file=.env.r2 --test --test-concurrency=1 test/freestyle/*.test.mjs` with `VOLUMES_TEST_PREPARE_SNAPSHOT=1`: 3 passed (the pause test was added and run right after, below).
- **Storage round trip** (`live.test.mjs`, 45.0 s): `checkStorage` ok; `checkSandbox` on a fresh VM ok, with warnings for the installs attach would do, and R2 answered its unauthenticated probe with HTTP 400. Attach, write as the `ubuntu` user (`uid: 1000`), inspect, detach `flushed: true`; reattach on a second VM read both files; a read-only mount rejected a write; `listMounts` showed both mounts; `detachAll` returned `flushed: true` for both; delete removed 4 objects (2 files and 2 directory markers).
- **Runtime** (`runtime.test.mjs`, 22.6 s): bootstrap on a fresh VM 15.1 s; `/dev/fuse` present; a `setsid` process and an rclone FUSE mount each outlived the exec that started them; every runtime check of `checkSandbox` passed (its storage check was given unusable keys on purpose).
- **Snapshot plus volume** (`snapshot.test.mjs`, 27.4 s): `createVolumeReadySnapshot` built the snapshot in 22.5 s and deleted its builder; on a VM booted from it, `checkSandbox` passed every check including storage ("rclone listed the namespace from inside the sandbox"), and **attach took 1.5 s**; the write round-tripped and detach flushed.
- **Pause and resume** (`pause.test.mjs`, 24.3 s): with a write still queued (`writeBackSeconds: 60`), the VM paused in 0.38 s and resumed in 0.07 s. The mount was `mounted` and responsive with the upload still queued; the queued file was readable, a new write succeeded, detach drained both (`flushed: true`), and a read-only reattach read both from R2. The first run of this test failed only on its own assumption of exactly 2 objects at delete; rclone also keeps directory markers, and the assertion now requires at least 2.
- **Second full run, same day**, with the documented command (`VOLUMES_TEST_PREPARE_SNAPSHOT=1 node --env-file=.env.freestyle --env-file=.env.r2 --test --test-concurrency=1 test/freestyle/*.test.mjs`): 4 passed, 0 failed. Round trip 41.9 s; pause 0.23 s and resume 0.66 s with the mount intact (24.1 s); runtime 23.0 s with a 15.1 s bootstrap; snapshot plus volume 28.7 s with attach at 1.3 s.
- **Probe, same day:** an equivalent one-off script first showed `/dev/fuse` present, a background process and a FUSE mount surviving across execs, and a 22.6 s snapshot build.
- **Still not run live:** stop/start recovery (covered in Docker), other VM sizes and arm64, throughput.

The same boundaries as before apply. Docker results are not Freestyle results. Large multipart boundaries are mocked rather than copied for real (no 5 TiB copy). Git coverage is unit, local smart HTTP and real FUSE, not live authenticated GitHub. The live run above covers the Freestyle behavior the snapshot helper and `checkSandbox` rely on; the VM TTL safety net was set on every test VM but never had to fire.
