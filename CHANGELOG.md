# Changelog

## 0.2.0 — 2026-09-25

First release on npm (`npm install freestyle-volumes freestyle`). It also ships every change merged to `main` since 0.1.0, listed after the new items.

- **npm package.** Publishable ESM package for Node 22+ with TypeScript types, declaration maps and source. Entry points `freestyle-volumes`, `/freestyle`, `/docker`, `/git` and `/package.json`; types also resolve under TypeScript's legacy `node10` resolution, and `require()` works on Node versions with `require(esm)`. `@aws-sdk/client-s3` is now a caret range rather than an exact pin, so consumers can share one copy. Builds start from a clean `dist/`.
- **CLI.** New `freestyle-volumes` command: `list`, `get`, `create`, `clone`, `delete`, `attachments`, `attach`, `inspect`, `detach`, `mounts`, `detach-all`, `doctor` and `prepare-snapshot`. Configuration comes from `VOLUMES_S3_*` and `FREESTYLE_API_KEY` (or `--env-file`), results print as JSON, progress goes to stderr, and exit codes separate operation failures (1) from usage and configuration errors (2). `--docker` targets a local container. Deleting requires repeating the name with `--confirm`.
- **Safe shutdown.** New `listMounts({ sandboxId })` reports every managed mount in a sandbox (`mounted` or `stale`, from its guest state record) and every rclone mount the library did not create, without taking locks. New `detachAll({ sandboxId, flushTimeoutMs?, force? })` detaches each managed mount in turn, never throws for an individual mount, retains recovery data for failures, leaves unmanaged mounts alone, and reports `flushed: true` only when nothing unflushed is left, so callers know when a VM is safe to delete or snapshot.
- **Preflight checks.** New `checkStorage()` probes the bucket from the host: reachability, listing, atomic conditional creates (a second `If-None-Match: *` write must be rejected, which catches providers that silently ignore the header), read-back and delete, using one probe object under `<prefix>/_doctor/` that is always deleted. New `checkSandbox({ sandboxId })` runs a read-only script in the sandbox: CPU, root, `/dev/fuse`, `fusermount3`, `flock`, rclone, `downloads.rclone.org` when rclone is missing, whether the sandbox can list the bucket with the exec-env credentials, and cache disk space, with a hint for every warning or failure. The CLI's `doctor [--vm]` prints both as a checklist.
- **Configuration from the environment.** New `storageConfigFromEnv(env?)` reads the `VOLUMES_S3_*` convention of the CLI, examples and live tests, and names every missing required variable.
- **Volume-ready snapshots.** New `createVolumeReadySnapshot(freestyle, options)` boots a temporary builder VM, runs the mount bootstrap (fuse3, flock, pinned and checksum-verified rclone), snapshots it and deletes the builder. The builder also gets a TTL as a safety net. VMs booted from the snapshot skip the one-time install on attach. No storage credentials are involved.
- **Freestyle adapter tests.** `FreestyleSandbox` now has unit tests for user selection, the 300 s exec cap, env forwarding and result mapping; `pnpm check:types` also proves the real SDK (now `freestyle@0.2.14`) satisfies the snapshot helper's structural types.
- **Release tooling.** `pnpm test:package` packs the tarball, installs it into a fresh project and exercises every entry point, the CLI bin and TypeScript resolution; `npm publish` runs it together with the unit tests and type checks. CI tests Node 22, 24 and 26. A release workflow publishes GitHub releases to npm with provenance (trusted publishing or `NPM_TOKEN`), and a manual workflow runs the billed Freestyle live tests from repository secrets.
- **Documentation.** README rewritten for npm users (install, quick start, snapshots, CLI, preflight, an agent-run recipe and seeding volumes without a VM, with [examples/agent-run.ts](examples/agent-run.ts)); [SECURITY.md](SECURITY.md) with private reporting and the trust boundary; release procedure in [docs/release.md](docs/release.md); verification record in [docs/evidence/v0.2.md](docs/evidence/v0.2.md).
- **Verification — 2026-09-25.** `pnpm test`: 146 passed, 0 skipped. `pnpm check:types`, `pnpm check:examples` and `pnpm test:package` passed. `VOLUMES_TEST_BOOTSTRAP=1 pnpm test:integration`: 33 passed, 0 failed, 0 skipped on local Docker (linux/arm64), including the CLI end to end, `detachAll` with crashed and unmanaged mounts, and the preflight checks against MinIO. `pnpm test:freestyle`: 2 skipped without credentials; no live Freestyle round trip or snapshot build has run yet.

Changes merged to `main` after 0.1.0, first released in 0.2.0:

- **Detach safety.** Use `rclone rcd` plus RC `mount/mount`: external normal unmount → FUSE serving stopped → retained VFS drained → process stopped. Queue/error counters must be valid and zero before reporting a verified drain.
- **Recovery.** `FLUSH_FAILED` may leave an unmounted filesystem with uploader, cache and state retained for retry. Failed attach retains recovery evidence. Forced uncertain detach retains state/cache in place and the advisory attachment record; rejected reattach preserves stopped-process evidence. Legacy state without identity metadata or with old cache ids is not automatically migrated and may require operator recovery.
- **Guest lifecycle.** Require per-path `flock`, reject symlink mount paths and ancestors, and verify PID start time, executable and socket argument before signaling. Stale mounts and existing processes require explicit detach rather than automatic replacement.
- **Storage identity.** Cache/mount ids include resolved host and sandbox endpoints, bucket, prefix, region, provider and path-style mode, plus volume/subpath/path. Credentials and request timeouts do not affect identity.
- **Registry and custom stores.** Validate stored records and exact data prefixes. New required `ObjectStore.putObjectIfAbsent` contract atomically creates records; S3 uses `If-None-Match: *` with no unconditional fallback. Concurrent creation preserves the winning record. Distributed attach/delete and create/delete races remain advisory and require application orchestration.
- **Clone.** Add `clone({ sourceVolumeId, name, labels?, allowLiveSource?, concurrency?, maxObjects?, maxManifestBytes? })`: same-bucket/namespace server-side copies with source ETag conditions, bounded concurrency (default 8, 1–64) and atomic conditional publication. Not a snapshot, COW fork or ACID transaction; caller quiescence is required and source attachment checks are advisory. Single `CopyObject` applies at or below the configured threshold (default 5 GiB); larger objects use multipart server-side copy up to a conservative 5 TiB per object. Selection hard caps are 100,000 objects and 32 MiB UTF-8 JSON manifest metadata; callers can lower them.
- **Generation layout.** New creates/clones write v2 records and isolated generation prefixes; valid legacy v1 records remain supported. Generation participates in cache identity. Older v1-only clients cannot read v2 records; coordinate namespace upgrades.
- **Multipart copy.** Add storage `multipartCopyThresholdBytes` and `multipartCopyPartSizeBytes` (integer bytes, 5 MiB–5 GiB). Part size defaults to 128 MiB and grows to keep at most 10,000 parts; parts run sequentially per object so clone concurrency also bounds part requests. HEAD validates selected size/ETag and pins an available version; each part enforces the ETag. Preserve supported content/user metadata and tags, with source version/tag and destination multipart/tag/abort permissions required. Export copy-limit/default constants from the package root. No client-payload fallback.
- **Clone recovery.** Retain immutable ownership intents on success/failure, with no automatic GC/resume. Unknown completion or publication retains data; other failed copies/cleanup are uncertain because remote work may finish after client failure and an empty listing. Expose multipart stage/upload/completion/abort diagnostics, including abort failures. Even acknowledged abort is not proof of destination absence. Reconcile provider uploads/late objects and configure incomplete-MPU lifecycle cleanup, never age-based generation deletion. Custom stores must enforce source ETags; conditional publication returning false must prove this call never wrote.
- **Git.** Export `VolumeGit`, `volumeGit`, `VolumeGitError` and types at the root and `/git`: explicit clone/status/path-selected commit with identity, clean ff-only pull, normal non-force push and directional sync. HTTPS/GitHub `owner/name`; tokens only via env and temporary askpass, never persistent URLs/config. Requires preinstalled Git and a trusted guest/adapter that never logs env. Hooks are disabled; filters, submodules, linked worktrees, symlinks and other unsafe configuration/layouts are rejected. No automatic commits, PRs or GitHub REST. Caller-enforced single writer, guest-local results and separate verified S3 detach, not ACID. Native active worktrees remain recommended. See [Git guide](docs/git.md) and [example](examples/git.ts).
- **Performance.** Add bounded metadata reads through `list({ concurrency? })` (default 8, 1–64) and opt-in `bufferSize`, `readAhead`, `readChunkSize`, `readChunkSizeLimit`, `transfers`. Defaults are unchanged; read-ahead only takes effect with full cache. The current-code [local MinIO rerun](docs/evidence/performance-local.md) on 2026-09-18 observed 2.86x list and 2.97x clone ratios of elapsed medians for concurrency 1 versus 8, including mandatory source HEAD checks. These are small single-copy, local host API measurements, not multipart throughput, Git, FUSE or Freestyle performance, or general speedup guarantees.
- **Documentation.** Add [performance and clone guidance](docs/performance.md) and [source-linked Freestyle research](docs/freestyle-research.md), separating native active workspaces, object artifacts and reviewable Git state. Preserve the tested retained-VFS detach protocol rather than substituting direct mount teardown.

## 0.1.0 — 2026-09-17

First preview. Historical release notes below describe the original implementation; the unreleased safety changes above supersede its detach and stale-mount behavior.

- **API.** `FreestyleVolumes` with `create`, `get` (with `create`), `list`, `delete` (confirmed, guarded by attachment records), `attach`, `inspectMount`, `detach`. Volumes are addressed by name; `subpath` and `readOnly` mounts.
- **Backend.** rclone FUSE mount (`--vfs-cache-mode writes`) over any S3-compatible bucket. Pinned rclone 1.75.1 with SHA-256 verification, or an existing rclone ≥ 1.68. Credentials only as environment variables. Unix-socket remote control drives flush-on-detach.
- **Lifecycle.** Readiness is a successful directory listing, not a started process. Detach expedites the upload queue and reports `flushed` honestly; `force` is explicit. Stale mounts after crashes or restarts are detected, cleaned and resumed on re-attach.
- **Integrations.** `freestyleSandboxes()` over the `freestyle` SDK (structural types, optional peer); `dockerSandboxes()` for local Linux containers.
- **Tests.** 33 unit tests; Linux integration suite on Docker + MinIO covering the full lifecycle, replacement, read-only, namespace and subpath isolation, bad credentials, unreachable storage, mount failure and timeout, missing FUSE, crash resume, busy mounts, flush failure and delete; opt-in bare-Ubuntu bootstrap test; a gated Freestyle live test (not yet executed).
